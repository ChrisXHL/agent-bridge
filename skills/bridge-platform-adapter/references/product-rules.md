# 产品规则

这些规则让每个平台在用户眼里是“同一个产品”。框架已经实现了大部分；写适配器
时不要绕开，也不要另加限制（不加人为的次数、长度、功能上限，只保留真正的安全
边界）。

## 1. 机器人模型

- **一个平台账号 = 一个机器人**。每个机器人独立拥有：名称、工作文件夹、业务
  Prompt、执行工具（Codex CLI / Claude Code CLI）、一条 Bridge 连接。
- 新接入的机器人自动建立同名工作文件夹 `~/AgentBridge/<名称>`（或
  `BRIDGE_WORKSPACE_ROOT`），默认名称是 `BOT_NAME`，重名自动加序号。
- **同一身份再次接入 = 刷新**，不新增：`bot_id`（或扫码模式下的
  `owner_user_id`）相同就更新凭证并重新启用，保留用户改过的名称、文件夹和 Prompt。
- 多个账号可以并存，互不影响。

## 2. 谁能使用

- 只服务**主人**：扫码模式是扫码的人（`owner_user_id`）；表单模式接入后先处于
  “等待配对”，面板显示 6 位配对码，主人在平台里**私聊**机器人发送
  `配对 123456`，第一个发对的人成为主人，机器人回复“配对成功”。
- 未配对时所有消息静默忽略；陌生人的消息静默忽略，不回复、不建任务。
- 需要多人使用时，覆盖 `is_allowed()` 做**明确的允许名单**，并在面板/文档里说明；
  永远不能返回“所有人都允许”。

## 3. 会话

- 会话按 **机器人 + 私聊/群 + 聊天 ID**（群里再加发送者）隔离。私聊历史不进入群，
  不同机器人、不同用户互不串。
- 同一会话的后续消息**接着同一个 Agent 会话**（`continue_from` 上一个任务）；
  上一条没完成时下一条排队，按顺序一条一条处理。
- 发送完整的 `新对话`、`重新开始对话` 或 `/new` 开始新会话，回复“好的，已开始新对话。”
- 每条消息一个任务记录，`request_id` 由消息 ID 生成，重复投递不会重复执行。

## 4. 消息进入任务

- 消息文字填入业务 Prompt 的 `{{message}}`（Prompt 为空则直接用原文）。
  Prompt 必须恰好一个 `{{message}}`。
- 附件（图片、文件、视频、语音文件）用该机器人自己的凭证下载到本机私有目录，
  在任务里写成“附件已保存在本机：<路径>”；下载失败写明失败，不要静默丢掉。
  平台自带的语音转文字可以直接作为文字。
- 只处理用户发来的消息；机器人自己或其他机器人的消息、系统事件不建任务。

## 5. 结果回传

- 任务结束（已完成 / 失败 / 已停止）后把结果发回**原聊天**；“需要你处理”时发一次
  提醒。完成但没有结果时回复“这次没有返回结果，请在 Bridge 面板查看。”
- 平台不支持 Markdown 时去掉标记（默认 `format_reply` 已处理）；超长按
  `REPLY_LIMIT` 分段。
- `send_text` 只有平台确认成功才返回 True；失败会在下一轮重试，不会重复发送已成功的。

## 6. 记住（长期规则）

- 主人说“记住……”“更新规则……”时，框架给这条任务附上一次性的规则入口
  （`scripts/update-platform-rule.py`，HMAC 令牌，24 小时有效）。Agent 把更新后的
  **完整业务 Prompt** 提交，直接改写这个机器人的 Prompt。
- 规则只存在 Bridge 里，不写进 Agent 自己的记忆文件或工作文件夹。

## 7. 停用与删除

- **停用**：停止接收新消息，保留任务和记录；可重新启用。
- **删除**：移除这个机器人的接入和 Bridge 连接（有执行中任务时拒绝），保留任务
  记录和工作文件夹；要恢复需重新接入。都需要在卡片上二次确认。
- 平台告知登录失效时，`receive` 抛 `SessionExpired`，面板显示“需要重新扫码/接入”，
  不再请求平台。

## 8. 用户需要亲自做的事

只有这些交给用户，并说清具体一步：在平台后台创建机器人/应用、官方扫码确认、
授权或管理员审批、在平台里发送配对码。其余（写代码、配置、重启、核验）由 Agent
完成，不要让用户去研究接口或填写技术字段。
