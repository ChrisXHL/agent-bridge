# 验收清单

接入成功、收发可用、执行可用要分开验证和汇报。离线通过不等于真实可用。

## 1. 离线

- [ ] `./scripts/verify-platform <id>` 显示“通过”
- [ ] `python -m unittest test_platform_channel` 通过（改过框架时必跑）

## 2. 隔离实例（推荐，不打扰正在用的 Bridge）

```bash
mkdir -p /tmp/bridge-try/work && BRIDGE_WORKSPACE_ROOT=/tmp/bridge-try/work .venv/bin/python service.py \
  --port 8899 --db /tmp/bridge-try/bridge.sqlite3 --projects /tmp/bridge-try/projects.json
```
打开 `http://127.0.0.1:8899/panel`：

- [ ] 左侧出现新平台，页面和“微信”页同一布局
- [ ] 接入卡能显示（二维码或表单），错误凭证给出可读的错误

## 3. 正式实例

重启前确认没有扫码进行中、没有执行中的任务。

- [ ] 用真实机器人接入；名称、工作文件夹自动建立
- [ ] 表单模式：在平台私聊发“配对 xxxxxx”，收到“配对成功”，状态变“已连接”
- [ ] 陌生账号发消息：没有任务、没有回复
- [ ] 发一条无敏感内容的消息 → 任务页出现任务 → 执行完成 → 结果回到原聊天
- [ ] 追问：Agent 记得上一句（同一会话）
- [ ] “新对话”后不再记得
- [ ] 文字 + 附件：附件保存到本机，Agent 实际读到了内容
- [ ] 群聊（平台支持时）与私聊互不串
- [ ] “记住：……”后设置页的业务 Prompt 已更新
- [ ] 停用后不再接收；重新启用后恢复；重启 Bridge 不重放旧消息

## 4. 汇报模板

> 已接入 **X**：机器人「…」已连接，工作文件夹 …，执行工具 …。
> 已验证：收发、续聊、新对话、附件（…）。未验证/还需要你：……

不要把“导入成功”“离线通过”说成全能力已验证。
