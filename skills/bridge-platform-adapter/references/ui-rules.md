# 界面规则

**所有平台页面长得一样**：和“微信”页同一套布局、样式类和文案。页面由
`static/platforms.js` 根据 `GET /api/platforms` 自动生成，适配器只提供元数据。
不要为单个平台写新的 HTML/CSS/JS，也不要另起设计风格。

## 适配器提供的元数据

| 字段 | 用在哪里 | 写法 |
|---|---|---|
| `LABEL` | 左侧导航、页面标题、提示文案 | 平台的通用叫法，如 `Telegram`、`钉钉` |
| `SUBTITLE` | 标题下一行 | “接入 X，在 X 里给助手派任务。” |
| `ICON` | 导航图标 | 24×24、`stroke-width:1.8` 线性图标的 `path d`；不用品牌彩色 Logo |
| `BIND_LABEL` | 主按钮 | `＋ 扫码接入X` 或 `＋ 接入X机器人` |
| `BIND_HELP` | 接入卡说明 | 一两句：去哪里拿凭证/在手机哪里打开扫码 |
| `BIND_FIELDS` | 表单接入的输入行 | 只放必需字段；凭证类 `secret: True` |
| `BOT_NAME` | 新机器人默认名 | `X 助手` |

## 页面结构（自动生成，供核对）

1. **导航**：在“微信”后面追加一项，图标 + 名称。
2. **工具栏** `.groups-toolbar`：只有一个主按钮 `BIND_LABEL`。
3. **接入卡** `.account-card`：
   - 扫码：二维码 240×240、“用手机扫一扫”、`BIND_HELP`、需要时的数字验证码输入；
     有效期 5 分钟，扫码中 1.5 秒刷新状态。
   - 表单：`.wx-group` 输入行 +「取消」「验证并接入」；错误就地显示在卡内。
4. **机器人列表** `.account-card` → `.account-bot-list`（两列，窄屏一列），每张
   `.account-bot` 卡片：
   - 名称 + 状态胶囊：已连接(done) / 正在连接(run) / 等待配对(wait) / 已停用(wait) /
     连接异常(fail) / 需要重新扫码·接入(fail)
   - “工作文件夹：<名称>”
   - 等待配对时显示“在 X 里私聊这个机器人，发送：配对 123456”
   - 「任务执行」下拉（Codex CLI · GPT / Claude Code CLI），切换后提示“只影响新任务”
   - 「设置」「停用/重新启用」「删除」；停用和删除用 `.bot-disable-confirm` 卡内确认
5. **设置页** `.wx-settings`（Apple 风格分组，只放必要字段）：
   顶栏「‹ X账号」/ 名称 /「保存」；分组一：名称、工作文件夹（更改…）；
   分组二：业务 Prompt；脚注“X消息会填入 {{message}}。在X里说「记住…」会直接更新这里。”
   有未保存修改时返回需确认。
6. 没有机器人时一句话：“还没有接入X。点击「…」开始。”

## 文案原则

- 中文、短句、说结果不说实现：“已接入”“已保存”“这次没能完成。”
- 不在界面展示 App Secret、Token、连接密钥、内部 ID。
- 错误信息由后端 `ValueError` 给出用户能懂的一句话，前端原样显示。

## 确实需要额外界面时

先确认产品规则里没有现成做法。需要的话扩展 `platforms.js` 的通用能力（例如新的
元数据字段），让所有平台都能用，并更新这份文档；不要写平台专属页面。
