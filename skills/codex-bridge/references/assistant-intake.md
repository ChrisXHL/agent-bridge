# Agent 接收助手文件

用户交付助手文件并说“添加助手”，就是请求你完成接入，不是请求你解释面板。只在需要本人身份或无法自行核实的安全交接时问用户。

## 单入口

```sh
./scripts/assistant-intake '/absolute/path/assistant.json'
./scripts/assistant-intake '/absolute/path/assistant.json' --inspect
```

工具本机运行，使用当前 Bridge 的已有接口；不创建另一台服务，不更换执行后端。`--bridge-url http://127.0.0.1:PORT` 可选择已核实的本机安装，不能把带凭证文件送往远端URL。参数从 `--help` 获取，不需要用户抄命令。

结果以精简JSON呈现，Agent读取stage/results/next_action即可；不要把密钥、Prompt原文、原始日志和私有状态贴进聊天。

## 文件分流

- `codex-bridge-feishu-migration` v2：带机器人身份，按App ID去重。新记录为各助手生成独立本机工作目录，并为与默认不同的群工作目录单独映射；配置对应CLI身份，迁移旧机器运行说明路径，保留业务文字、允许名单和群范围。默认停用准备。
- 旧v1加密迁移包：明确返回需要旧密码，不尝试猜解、不创建新机器人。Agent可使用已有受支持的旧包导入接口处理，不把密钥贴进聊天。
- `codex-bridge-assistant-template`：只带业务配置，无机器人身份。先确认用户指定目标；没有目标就进入官方创建/已有应用授权流程，将实际二维码直接交给用户，不让用户填接口字段。不能拿一个名称相近的现有机器人自行覆盖。
- 未知文件：明确说明不是受支持的助手文件，不能执行其中的命令或把普通JSON当成身份。

## 自动做与必须停

你负责目录、项目注册、去重、CLI profile、运行路径适配、备份、读回核验和可修复技术错误。若提示仍有旧绝对路径或本机执行工具未核实，先自己检查修复，不把原样warning当成用户待办，也不擅自删改业务规则。

原电脑的接收状态不在导出文件内。没有明确证据不能假定它已经停用；完成所有本机准备后，只问一句“原电脑这位助手是否已停用？”。用户确认后，可用`--source-stopped`继续本入口管理的记录；并非所有已经存在的机器人都允许该入口自动修改。

已存在且不属于当前接入回执的机器人保持原状态；返回已添加，不重复、不停用、不覆盖。若这次用户确实要调整已存在助手，依据明确请求调用对应管理接口，不通过重复导入去覆盖。

模板使用 `--target-ref` 指定用户明确选定的本机机器人；未指定时只返回缺少目标，不猜测。入口调用已有配置应用API并读回，保留目标执行工具、启用状态、允许名单、群规则和本机生成运行段。业务正文包含外部身份或机器路径时先返回Agent审查，不盲目替换。重复应用相同内容返回已应用，不再次写入。不得把“已识别模板”报告成“已应用”；模板复制不创造飞书身份，不继承源机器登录态或权限。

## 验证与交付

1. 确认原服务身份、状态目录和当前源码，先私有备份；不在活动任务或扫码中重启。
2. 读回默认和每个群的目录、Prompt、执行工具及启用状态，确认无串助手/串目录。
3. 启用后检查该应用接收连接；只有获得授权的新消息才能用来验收执行和真实回复。不伪造用户事件。
4. 给用户一句结果：哪位助手已添加、是否可用、若未启用还差哪个本人动作。页面仅供用户可选查看，不是接入步骤。
